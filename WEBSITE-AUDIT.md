## Part 0 — TL;DR for the AI assistant

If you are an AI reading this to help with a 3D feature, here are the ten facts that matter most:

1. **Stack:** React 18 + Vite 5 + Tailwind 3 + React Router 6. **No TypeScript. No SSR.** Plain `.jsx`.
2. **Deployment:** static build → **Hostinger shared hosting** (Apache/LiteSpeed). **No Node runtime in production.** The only backend is one PHP file.
3. **Language:** all UI copy is **French**. Keep it French.
4. **Two coexisting design systems** (`index.css` "clay" and `zenvira.css` "olive"). This is deliberate. See Part 3 — *read this before styling anything*.
5. **Styling is CSS-variable-driven.** Never hardcode a hex. Use the tokens.
6. **Scroll animation contract:** any element with `data-reveal` gets faded in by one IntersectionObserver. Add the attribute, get the animation free.
7. **Assets are absolute-rooted** (`/media/...`, `base: '/'`). Relative paths break on `/projets/:slug`. This was a real bug that was fixed — do not reintroduce it.
8. **`prefers-reduced-motion` is respected everywhere.** Any 3D you add must respect it too.
9. **Current JS payload: 78 KB gzipped total.** Three.js would be ~5× the entire current bundle. This is the central trade-off of the 3D project — see Part 9.
10. **There is a strict CSP** in `.htaccess` (`script-src 'self'`). A CDN-loaded 3D library **will be blocked**. Bundle it instead.

## Part 1 — What this website is

**Akoubri** is a French-language marketing/portfolio site ("site vitrine") for a fictional-but-realistic Moroccan **architecture and interior design studio** based in Marrakech and Casablanca.

It sells four services: architecture, interior design, **3D renderings/CGI** (`images de synthèse`), and art direction.

> **Note the irony, and the opportunity:** the studio's *pitch* is "we render before we build — decide on images, not promises." A real 3D experience on the site is therefore not decoration; it is the thesis of the business made literal. That is the strongest possible justification for the 3D work you are planning.

```
        └── data/          ← projects.js  (all content)

public/                    ← copied verbatim to the server root
├── media/                 ← 55 jpg, 4 video files  (17 MB)
├── fonts/                 ← 17 self-hosted woff2   (372 KB)
├── api/contact.php        ← the entire backend
├── .htaccess              ← SPA routing, cache, CSP, HTTPS
├── robots.txt
└── sitemap.xml
```

### Key architectural decisions (and why)

**No SSR.** Titles are set imperatively in `RouteEffects` inside [App.jsx](src/App.jsx#L45-L60) — a `useEffect` on `pathname` that also scrolls to top. The code comments this honestly: *"Without an SSR layer this is the only place titles can be maintained."*

**Client-side routing on Apache.** [.htaccess](public/.htaccess) rewrites every non-file request to `index.html` so deep links survive a refresh.

**`base: '/'` is load-bearing.** [vite.config.js](vite.config.js) carries a long comment explaining that `'./'` broke two-level routes: on `/projets/le-sentier`, relative asset URLs resolved to `/projets/assets/...` and 404'd. **All media paths are absolute for the same reason.**

**Manual vendor chunk.** React + ReactDOM + Router are split into `vendor.js` so app-code changes don't invalidate the framework cache.

## Part 3 — The design system (⚠️ the most important section)

**There are two complete, coexisting design systems.** Any AI that misses this will produce visually wrong code. Understand the contract before touching styles.

### System A — "Clay / Paper" ([src/index.css](src/index.css))

The original system. Warm, paper-like, editorial. Serif display face.

```css
--ink: #1c1917;        /* near-black text        */
--paper: #faf8f5;      /* warm off-white ground  */
--sand: #f2ede6;       /* alt band               */
--clay: #b06b3a;       /* BRASS ACCENT — the logo/signage colour */
--font-display: 'Fraunces', Georgia, serif;   /* serif  */
--font-body: 'Inter', sans-serif;
```

Loaded from **Google Fonts** via `<link>` in `index.html`.

### System B — "Zenvira / Olive" ([src/zenvira.css](src/zenvira.css))

Ported from a reference template. Cooler, architectural, condensed **uppercase** display face. This is the **dominant** system — most sections use it.

A strict 9-step ordered ramp, darkest → white:

```css
--zv-primary:     #202918;  /* darkest olive — text, dark bands, buttons */
--zv-muted:       #34402c;  /* secondary text                            */
--zv-border-dark: #4b5243;  /* rules on dark                             */
--zv-gray-400:    #646662;  /* placeholder / meta                        */
--zv-gray-100:    #a1a49a;  /* de-emphasised display text                */
--zv-border:      #cccbc2;  /* rules on light                            */
--zv-bg-alt:      #ede9df;  /* panels, alt bands                         */
--zv-bg:          #f7f4ec;  /* page ground                               */
--zv-white:       #ffffff;  /* cards                                     */

--zv-display: 'Fjalla One', 'Arial Narrow', sans-serif;  /* condensed, UPPERCASE */
--zv-body: 'Poppins', sans-serif;
```

**Self-hosted** woff2 in `/public/fonts/` (17 files, 372 KB).

The source comment explains why the ramp works: *"It is a single ordered ramp from the darkest olive to white, which is what makes it read as a system: every surface, rule and text tone on the site is one of these steps, never an ad-hoc tint."*

### 🔑 The scoping contract — memorize this

> **The `.zv` tokens and utilities are OPT-IN. Nothing in `zenvira.css` styles a bare element.**
> A section adopts the olive theme **only** by carrying the `.zv` class.

```jsx
<section className="zv zv-section">   {/* olive theme, Fjalla+Poppins */}
<section className="section-y">        {/* clay theme, Fraunces+Inter  */}
<section className="zv zv-dark">       {/* dark olive band, white text */}
<section className="zv zv-alt">        {/* #ede9df alt ground          */}
```

**Sections deliberately kept in System A** (marked `PROTECTED` in [Home.jsx](src/pages/Home.jsx#L9-L15) — these are approved designs, do not restyle):
- `Header` / `Footer`
- `Featured` — "Projets récents"
- `Showcase` — "Les espaces que vous imaginez"
- `Testimonials` — "Ce qu'en disent les maîtres d'ouvrage"

**Both font systems are genuinely in use** — I verified 15 `font-display`/`display-*` usages across 7 files. This is dual-system by design, not dead code.

### Why a substitution was made (good detail to know)

The reference used **Bayon** for display. Bayon is Khmer-first: its Latin subset has **no accented glyphs** (É À Û Ç Ô è é all absent), yet its `@font-face` still declares `U+0000–00FF`. The browser selected it, failed per-character, and fell back mid-word — catastrophic on a French site. **Fjalla One** replaced it as the nearest condensed single-weight face with full Latin Extended coverage. Documented in [public/fonts/zenvira-fonts.css](public/fonts/zenvira-fonts.css).

### Typography scale

Fluid `clamp()` with **explicit phone floors**. The comments record a real bug: the `clamp()` vw term only cleared its floor at ~688px for `h1` and ~1111px for `h5`, so **on phones every heading sat frozen at its desktop minimum** and the fluid middle never ran. Fixed with hard overrides at `640px` and `380px`.

```css
--zv-h1: clamp(2.75rem, 6.4vw, 5.5rem);   /* 88px desktop */
@media (max-width: 640px) { --zv-h1: 2.25rem; }  /* 36px */
@media (max-width: 380px) { --zv-h1: 2rem; }     /* 32px */
```

### Shape language

| Token | Value | Meaning |
|---|---|---|
| Buttons | `border-radius: 100px` | full pill |
| Cards | `20px` | flat, hairline border, **no shadow** in System B |
| Panels/tiles | `24px 24px 0 0` | **top-only rounding** |
| Media cards (System A) | `24px` outer / `14px` inner well | with shadow |

**Top-only rounding is a signature move.** From the source: *"the reference rounds these panels on their TOP corners only, so a stacked column reads as one continuous run of surfaces rather than a set of detached cards."* **Match this if you add a 3D viewer panel.**

### Motion

```css
--ease-arch: cubic-bezier(0.22, 1, 0.36, 1);  /* the house easing */
--ease-soft: cubic-bezier(0.4, 0, 0.2, 1);
```

Durations: micro 140–300ms · standard 400–620ms · reveals 900–1200ms.

## Part 4 — How the interactions work

### Scroll reveal — the site's core animation contract

[src/hooks/useReveal.js](src/hooks/useReveal.js). **One** IntersectionObserver per mount watches every `[data-reveal]` element, adds `.is-visible` once, then **unobserves** it (stays cheap on long pages).

```jsx
<div data-reveal className="reveal">…</div>                      {/* fade + rise 28px */}
<div data-reveal data-reveal-delay="120" className="reveal">…</div>  {/* stagger */}
<div data-reveal className="mask-reveal">…</div>                  {/* clip-path curtain wipe */}
```

Threshold `0.12`, rootMargin `0px 0px -8% 0px`. Accepts a `deps` array to re-scan after route/filter changes. **If reduced-motion is set or IO is unavailable, everything is shown immediately** — never hidden.

### Header — [Header.jsx](src/components/Header.jsx)

Two separate headers (desktop `lg:block`, mobile `lg:hidden`), both floating pills with `backdrop-blur-xl` and an animated 4s gradient "sweep". Hides on scroll-down past 90px, returns on scroll-up.

Two accessibility details worth preserving:
- The closed mobile drawer is only *transparent*, so it carries `inert` + `aria-hidden` — otherwise its 5 links stay in the tab order.
- Body lock uses **`overflowY`, not the `overflow` shorthand** — the shorthand would overwrite `overflow-x: clip` and turn body into a scroll container, **silently killing `position: sticky`** on every descendant.

### Showcase carousel — [Showcase.jsx](src/components/Showcase.jsx)

Three panels: centre is a plain rectangle; the flanking two are **clipped into mirrored trapezoids** via `clip-path: polygon(...)` that lean inward.

> *"the slabs read like a plan cut through the building, which is why the shape suits an architecture practice rather than being decoration for its own sake."*

Keyboard (←/→), swipe (45px threshold), dots. Neighbours preloaded. **Only the centre slide is interactive**; side panels are `aria-hidden`, and an `aria-live` region announces changes. On phones the trapezoids become square slivers — *"at this width a trapezoid reads as a rendering glitch rather than a cut."*

### Testimonial wall — [Testimonials.jsx](src/components/Testimonials.jsx)

3 columns, pure-CSS infinite vertical drift (`translateY 0 → -50%`, cards rendered twice). Column 2 runs **reverse** so neighbours don't move in lockstep. Different speeds (46s/58s/52s). Gradient mask feathers top/bottom. Pauses on hover. **Duplicated cards carry `aria-hidden` so quotes aren't announced twice.** Monogram discs instead of photos, because *"inventing portraits of clients who did not sit for one would be a lie."*

### Video handling — [ProjectCard.jsx](src/components/ProjectCard.jsx)

**Directly relevant to 3D.** Playback is **gated on visibility**: off-screen cards stay paused, *"so a grid of clips does not decode four videos at once on a phone."* Also respects `prefers-reduced-motion` **and** `navigator.connection.saveData`, leaving the poster in place.

> **Apply this exact pattern to any 3D canvas.** Render only when visible; never run a WebGL loop off-screen.

### Custom Select — [Select.jsx](src/components/Select.jsx)

A full ARIA listbox replacing the native control (whose OS-drawn popup can't be styled). Implements focus management, type-ahead with 700ms reset, full keyboard map, outside-pointerdown close, scroll/resize close on desktop, and a **bottom sheet on touch** with body-scroll lock. Genuinely high-quality work.

## Part 5 — Backend & deployment

**The entire backend is [public/api/contact.php](public/api/contact.php)** — one PHP file, because Hostinger shared plans have no Node runtime.

Three forms post JSON to it: `/contact` (full), `/projets/:slug` (quote, prefixes `[Projet : X]`), `/services` (CTA).

Its protections are solid:

| Protection | Implementation |
|---|---|
| Method guard | POST only → 405 |
| Size cap | 20 KB → 413 |
| Honeypot | `company` field; **returns 200 so the bot thinks it won** and doesn't retry |
| Rate limit | 60s per IP, SHA-256 lockfile in temp dir → 429 |
| Header injection | strips `\r`, `\n`, `%0a`, `%0d` from all header-bound fields |
| Validation | name ≥2, `FILTER_VALIDATE_EMAIL`, message ≥20 |
| Length caps | name 120, email 180, message 5000 |
| Encoding | Base64 UTF-8 subject; `-f` envelope sender |

`.htaccess` handles: forced HTTPS, SPA rewrite, gzip, 1-year immutable cache on fingerprinted assets, `no-cache` on HTML, `Options -Indexes`, dotfile denial, and a full security header set including a **strict CSP**.

## Part 6 — Audit findings

Nothing here is critical. The codebase is above average — dense, accurate explanatory comments; consistent naming; real accessibility work; several genuinely hard bugs already found and fixed. Findings are ordered by value.

### 🔴 1. `showreel.mp4` is 10 MB of dead weight — *fix this first*

**Verified: `public/media/video/showreel.mp4` (9.96 MB) is referenced nowhere** in `src/`, `index.html`, or `dist/index.html`.

It is **58% of your entire 17 MB media folder**, and `public/` is copied verbatim into the build — so it ships to the server and consumes Hostinger disk/bandwidth for nothing.

```bash
rm public/media/video/showreel.mp4   # 17 MB → 7 MB
```
*(If you intend to use it later, keep it outside `public/` until then.)*

### 🟠 2. Real bug — `Select` silently drops its accessibility props

In [Contact.jsx](src/pages/Contact.jsx#L293-L298), `Field` clones its child and injects:

```jsx
cloneElement(children, { 'aria-invalid': 'true', 'aria-describedby': errorId })
```

But [Select.jsx](src/components/Select.jsx#L17-L27) destructures **`invalid`** and **`describedBy`** — not `aria-invalid` / `aria-describedby`. React does not forward unknown props to a custom component, so **both are discarded.**

*Impact:* limited today (the two Select fields — mission, budget — are optional and never set an error), so it is latent rather than active. But the CSS rule `.zv-field[aria-invalid='true']` will never fire on a Select, so the moment you make one required, its error state will be invisible to both screen readers and the red-border style.

**Fix** — in `Field`, branch on whether the child is a custom `Select`:

```jsx
const control = isValidElement(children)
  ? cloneElement(children, {
      ...(error
        ? custom
          ? { invalid: true, describedBy: errorId }              // Select's API
          : { 'aria-invalid': 'true', 'aria-describedby': errorId }  // native
        : null),
      ...(custom ? { 'aria-labelledby': labelId } : null),
    })
  : children;
```

### 🟠 3. No social / structured-data meta tags

`index.html` has `title` and `description` only. **Zero** Open Graph, Twitter Card, canonical, or JSON-LD (verified: 0 matches).

*Impact:* a link shared on WhatsApp, LinkedIn or Instagram — the channels an architecture studio actually lives on — renders as a bare grey box with no image. For a visual portfolio that is a real loss.

Add to `<head>`:

```html
<link rel="canonical" href="https://akoubri.com/" />
<meta property="og:type"        content="website" />
<meta property="og:site_name"   content="Akoubri" />
<meta property="og:locale"      content="fr_FR" />
<meta property="og:title"       content="Akoubri — Cabinet d'architecture & design d'intérieur" />
<meta property="og:description" content="Résidences, villas et espaces de travail au Maroc." />
<meta property="og:image"       content="https://akoubri.com/media/le-sentier/sentier-05.jpg" />
<meta property="og:url"         content="https://akoubri.com/" />
<meta name="twitter:card"       content="summary_large_image" />
```

Plus `ArchitecturalService` JSON-LD (name, address, telephone, sameAs, areaServed) — strong for local search in Marrakech/Casablanca.

**SPA caveat:** these are static, so every route shares the homepage's card. Per-page cards need pre-rendering (see finding 6).

### 🟡 4. Meta description not updated per route

`RouteEffects` sets `document.title` per route but leaves `<meta name="description">` at the homepage value on all 7 pages. Cheap fix in the same effect:

```js
document.querySelector('meta[name="description"]')?.setAttribute('content', DESCRIPTIONS[pathname] ?? DEFAULT);
```

### 🟡 5. Images are JPEG-only — no WebP/AVIF

55 JPEGs, none over ~230 KB (already well compressed), but **no modern formats and no `srcset`**. Phones download desktop-width files.

WebP typically saves 25–35%. Because `width`/`height` are already set everywhere (good — no CLS), adding `<picture>` is low-risk:

```bash
for f in public/media/**/*.jpg; do cwebp -q 82 "$f" -o "${f%.jpg}.webp"; done
```

### 🟡 6. No pre-rendering — SEO ceiling for a portfolio

The server returns an empty `<div id="root">`. Google executes JS and will index it, but **social crawlers and most AI/LLM crawlers do not** — they see nothing. For a business whose value is visual proof, this caps discoverability.

`vite-plugin-ssg` or `react-snap` would emit real HTML per route at build time while keeping the pure-static Hostinger deployment. **This is also the single best thing you can do for AI-search visibility.**

### 🟢 7. Dead CSS (~150 lines)

Verified unused in any `.jsx`: `.blueprint-grid`, `.blueprint-fade`, `.hero-shell`, `.rail` + `railScroll`, `.animate-word` + `wordIn`, `.faq-pill`, `.panel-dark`, `.zoom-parent`, `.btn-on-dark`.

Note `.btn-light` (System A) is also unused — Home uses `.zv-btn-light` (System B). Easy to confuse; they are different classes.

Harmless (gzip handles it), but it's misleading scaffolding for anyone reading the file later. `.blueprint-grid` in particular is a *drafting-sheet* pattern — **consider keeping it, it may be useful as a backdrop for a 3D viewer.**

### 🟢 8. Placeholder contact details ship to production

`contact@akoubri.com` and `+212 6 00 00 00 00` appear in Header, Footer, Contact, and `contact.php`. Real values must be set in **all four** before launch, and the `no-reply@` mailbox must exist in hPanel or Hostinger rejects the mail as spoofed.

- **Duplicated `values` array.** The 3 core values in [Home.jsx](src/pages/Home.jsx#L329-L333) are copy-pasted from [Agency.jsx](src/pages/Agency.jsx#L5-L36) (which has 6) with slightly different wording. Move to `projects.js`.

## Part 7 — Conventions to follow when adding code

1. **French UI copy**, `'` typographic apostrophes, `&nbsp;` before `?` and `!`, non-breaking thin space in numbers (`4 200 m²`).
2. **Tokens only** — `var(--zv-primary)`, never `#202918`.
3. **Decide the theme first** — does the section carry `.zv` or not?
4. **Add `data-reveal` + `reveal`** for scroll animation; `data-reveal-delay` for stagger.
5. **Absolute media paths** — `/media/...`, never `media/...` or `./media/...`.
6. **Always set `width` and `height`** on images.
7. **`loading="lazy"`** below the fold; `fetchpriority="high"` for LCP images; **never lazy inside a translated track**.
8. **Respect `prefers-reduced-motion`** in any new animation.
9. **Decorative media** gets `alt=""` + `aria-hidden="true"`.
10. **Touch targets ≥ 44px** (see the dots pattern in `Showcase.jsx`).
11. New content goes in `data/projects.js`, not inline in a page.

**PROJECT CONTEXT — Akoubri architecture studio website**

I have a French-language architecture-studio portfolio site and I want to add 3D features. Here is the full technical context.

**Stack:** React 18.3 + Vite 5.4 + Tailwind 3.4 + React Router 6.26. JavaScript only, **no TypeScript**. No SSR — pure client-side SPA. **Current bundle (this is important):** vendor 53 KB gzip + app 25 KB gzip + CSS 13 KB gzip ≈ **91 KB gzipped total**. The site is deliberately very light.

**Structure:** `src/{components,pages,hooks,data}`. All content — 4 projects, services, stats, testimonials, FAQ — lives in one file, `src/data/projects.js`. Static assets in `public/media/` (55 JPEGs, ~7 MB after removing an unused video), fonts self-hosted in `public/fonts/`.

**⚠️ TWO COEXISTING DESIGN SYSTEMS — critical:**

**Scoping contract:** System B is **opt-in** — nothing in `zenvira.css` styles a bare element. A section adopts it only by carrying the `.zv` class. Modifiers: `.zv-dark` (dark olive band, white text), `.zv-alt` (`#ede9df` ground), `.zv-section` (100px vertical padding, 64px mobile). Sections WITHOUT `.zv` stay in System A. **Design language:**
- Buttons: full pill (`border-radius:100px`), `.zv-btn`, `.zv-btn-outline`, `.zv-btn-light`.
- Cards: `20px` radius, `1px solid var(--zv-border)`, **flat — no shadows in System B**.
- Panels/tiles: **top-only rounding `24px 24px 0 0`** — a signature move so stacked panels read as one continuous run of surfaces. Match this.
- Easing: `--ease-arch: cubic-bezier(0.22,1,0.36,1)` (house easing), `--ease-soft: cubic-bezier(0.4,0,0.2,1)`.
- Layout: `.shell` = `max-width:1320px` + `--gutter` padding.
- Type: fluid `clamp()` with explicit phone floors at 640px/380px.
- **Never hardcode a hex — always use the CSS variables.**

**Animation contract:** any element with `data-reveal` + class `reveal` is faded in (28px rise, 900ms) by a single IntersectionObserver in `src/hooks/useReveal.js`, which unobserves after firing. `data-reveal-delay="120"` staggers. `prefers-reduced-motion` is respected **everywhere** and must stay respected.

1. **Strict CSP in `.htaccess`:** `script-src 'self'` — **external CDN scripts are blocked**. Any 3D library must be npm-installed and bundled by Vite, never loaded from a CDN.
2. **All asset paths must be absolute** (`/media/...`). `base:'/'` in `vite.config.js`. Relative paths break on two-level routes like `/projets/le-sentier` — this was a real bug that was fixed.
3. All UI copy is **French** — keep it French.
4. Media is served from Hostinger shared hosting — bandwidth and CPU are modest.
5. Videos already use **visibility-gated playback** (IntersectionObserver play/pause) and respect `navigator.connection.saveData`. Apply the same discipline to any WebGL canvas.

## Part 9 — Planning the 3D addition

### The central trade-off — be honest about it

| Library | gzipped | vs. current 91 KB site |
|---|---|---|
| `three` (full) | ~150 KB | **+165%** |
| `three` (tree-shaken, core + `GLTFLoader` + `OrbitControls`) | ~100 KB | +110% |
| `@react-three/fiber` + `drei` on top | +40–70 KB | — |
| `<model-viewer>` (web component) | ~180 KB | but **lazy-loadable**, near-zero API |

Plus the models themselves: a Draco/Meshopt-compressed GLB of an architectural scene is realistically **2–15 MB**.

**Therefore the single most important rule: never let 3D touch the initial bundle.**

```js
const Viewer = lazy(() => import('./components/Model3D'));  // its own chunk
```

Then gate on visibility (`IntersectionObserver`) — or better, on an explicit click ("Voir en 3D"). The site already proves this discipline with video; reuse it.

### Recommended options, in order

**Option A — Per-project GLB viewer (best value).** Add an optional `model` key to a project; render a lazy `<model-viewer>` or R3F canvas inside a `.zv-panel-media` block on `/projets/:slug`. Fits the existing top-rounded panel language exactly, and is genuinely useful — this is a studio that sells renderings.

```js
{ slug: 'le-sentier', /* … */ model: '/media/3d/le-sentier.glb', modelPoster: '/media/3d/le-sentier-poster.jpg' }
```

**Option B — 360°/panorama interior tours.** An equirectangular sphere is far cheaper than a full model and maps perfectly onto the *"Visites virtuelles"* service already advertised in `services[2].points`. Highest business value per KB.

**Option C — Subtle WebGL hero.** Highest risk: the hero is the LCP element and currently a well-optimised 1.3 MB video loop. Only worth it if the 3D genuinely beats that, and it must keep the video/poster fallback.

**Option D — Frame-sequence pseudo-3D.** 36–72 pre-rendered JPEGs scrubbed on drag. **Zero WebGL, zero library, works everywhere**, and the studio already produces renders. Cheapest credible "3D" — a strong pragmatic first step.

### Non-negotiable checklist for whatever you build

- [ ] **Lazy-load** the library — never in the main chunk.
- [ ] **Bundle it via npm** — the CSP (`script-src 'self'`) blocks CDNs.
- [ ] **Poster image first**; load 3D on click or on intersection.
- [ ] **Pause `requestAnimationFrame` when off-screen** — mirror `ProjectCard.jsx`.
- [ ] **Respect `prefers-reduced-motion`** — no auto-rotate; show the poster.
- [ ] **Respect `navigator.connection.saveData`** — as the videos already do.
- [ ] **Check WebGL support**, fall back to the poster/gallery.
- [ ] **Compress models** — Draco or Meshopt; target < 5 MB.
- [ ] **Absolute paths** — `/media/3d/…`.
- [ ] **Keyboard accessible**, with a text alternative; canvas gets a label.
- [ ] **Style to System B** — top-only `24px 24px 0 0` radius, `var(--zv-border)`, no shadow.
- [ ] **French labels** — "Voir en 3D", "Visite virtuelle", "Chargement…".
- [ ] **Dispose geometries/materials/textures on unmount** — WebGL leaks are not garbage-collected.
- [ ] **`.htaccess`:** add a cache rule + correct MIME type for `.glb`.
- [ ] **Test on a mid-range Android**, not just desktop.

### CSP note

The current policy has **no** `worker-src`. Draco and Meshopt decoders commonly run in a worker, and some loaders use `blob:` URLs. If you hit a console CSP error, you will likely need:

```
worker-src 'self' blob:;
```

Add it only if required, and keep the rest of the policy strict.
